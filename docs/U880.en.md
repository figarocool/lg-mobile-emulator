# U880 V10b: operation and limitations

[Italiano](U880.md) · [Setup](INSTALLATION.en.md)

The original CODE is identified by its hash. Encrypted input is decoded using
the user's local key; plaintext input does not need a key. Both paths must
produce the expected V10b AMSS hash.

Installation runs original filesystem routines to build simulated flash,
imports and verifies MODULE/MEDIA, and initializes a UI database preference.
Firmware instructions are not patched. Factory metadata, USIM and surrounding
hardware are synthetic and do not represent the contents of a physical phone.

The window starts from a CPU reset using prepared flash, then saves a separate
snapshot on normal exit. USIM reset/ATR, ICCID/IMSI reads, the original home
screen and Messages navigation have been observed. The USIM model now updates
the current directory after selecting an EF by an absolute path; this fixes
the previous subsequent-read failure in the driver.

Support remains partial: inferred GPIOs, approximate timing/IRQs, experimental
key mapping, and no complete U880 radio model. Not every application, calling,
camera or U880 audio has been verified. V10a remains a diagnostic profile.
